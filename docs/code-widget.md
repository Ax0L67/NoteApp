# Виджет исполняемого кода

Вставка: редактор заметки → «Вставка» → «Код». В меню «⋯» доступны Python
и C++, имя файла, сохранение кода и переключение между плавающим блоком
и обычным блоком в тексте. Плавающий блок использует существующие настройки
размера, положения, цвета и текстуры. В режиме чтения код также отображается
виджетом. Код и stdin сохраняются в Markdown; консоль и доверие — нет.

## Локальные среды

- Python: Pyodide 0.27.7 с включённой стандартной библиотекой из npm-архива.
- C++17: browsercc 0.1.1, Clang/LLD и sysroot из npm-архива.
- Все необходимые файлы находятся в `public/code-runtime`; Vite копирует их
  в сборку. Docker, системные интерпретаторы, CDN и облачные компиляторы
  не используются. Дополнительные пакеты Python не загружаются.
- Ориентировочный размер среды — 100 МиБ до сжатия. Происхождение файлов
  и лицензии перечислены в `public/code-runtime/NOTICE.md`, версии и хеши —
  в `versions.json`. Перед публичным распространением нужны полные notices
  включённых сторонних компонентов.

## Исполнение и изоляция

Запуск разрешён только явной кнопкой. Перед первым выполнением конкретного
кода запрашивается подтверждение; оно хранится лишь в памяти текущего окна,
привязано к заметке, блоку, языку и SHA-256 исходного текста. Изменение кода
требует нового подтверждения. Импорт Markdown не переносит разрешение.

Rust-команды `prepare_code_run` / `release_code_run` проверяют язык и размер
входа, а также резервируют один запуск для всего приложения, независимо от
состояния хранилища заметок. Shell-команды и дочерние системные программы
для исполнения не используются. `save_code_file` сохраняет код отдельно
через системный диалог и не принимает путь из заметки.

Сам WebAssembly выполняется в отдельном Worker внутри iframe с
`sandbox="allow-scripts"`, без `allow-same-origin`. В Tauri статическая
страница iframe обслуживается отдельным протоколом `note-code`; его CSP
не ослабляет правила основного окна приложения. Страница не вставляет
пользовательский код в JavaScript: код передаётся отдельным сообщением.
Обмен с основным окном идёт через MessagePort; принимаются только вывод,
статус и ошибки, без команд к файлам или нативным API.

Вложенная CSP запрещает сеть, внешние скрипты, формы, объекты и навигацию
через базовый URL. Python получает только виртуальную файловую систему
Pyodide, C++ — дескрипторы stdin/stdout/stderr и ограниченные WASI-функции.
Файлы компьютера, хранилище NoteApp, Docker socket, shell и Tauri IPC
в исполняющую среду не передаются.

Перед включением запуска приложение выполняет независимую проверку Worker:
непрозрачный origin, отсутствие Tauri/DOM, недоступность IndexedDB и реальные
CSP-нарушения при попытках обращения к сети и внешнему скрипту. Отказ,
неподдерживаемая проверка или тайм-аут оставляют кнопку отключённой.
Отсутствующий файл среды также приводит к ошибке без небезопасного fallback.

## Ограничения и остановка

- Подготовка и компиляция: 60 секунд; выполнение: 10 секунд.
- Суммарный stdout/stderr: 1 МиБ, проверяется и в Worker, и принимающим окном.
- Код: 128 КиБ; stdin: 64 КиБ в UTF-8. Ввод передаётся заранее, затем EOF.
- Линейная память Wasm программы: 256 МиБ. Для C++ ограничены также
  памяти отдельных стадий компилятора: 256 + 512 + 256 МиБ.
- Это ограничения **линейной памяти Wasm**, а не жёсткая квота общей памяти
  процесса WebView. JavaScript-обвязка и буферы требуют дополнительной RAM;
  намеренно вредоносный Python/JavaScript всё ещё способен исчерпать ресурсы
  браузерного процесса. Не следует считать эту реализацию защитой от всех DoS.
- «Стоп» завершает Worker; после завершения, ошибки и тайм-аута удаляются
  iframe, MessagePort и blob URL, освобождается резервирование Rust.
- Переключение режима чтения и изменение положения виджета сохраняют сеанс
  по ID блока. Удаление виджета и закрытие заметки останавливают запуск.

## Проверки

- `npm test` — Markdown, настройки, декорации и остальные тесты приложения.
- `cargo test --manifest-path src-tauri/Cargo.toml --offline code_runtime`
  — проверки Rust, разрешённого маршрута iframe, CSP и резервирования.
- `node scripts/test-code-engines.mjs` — реальные локальные Wasm-движки:
  Python/C++, stdin/EOF, Unicode, ошибки, exit code, предел вывода,
  ограничение линейной памяти C++, остановка и тайм-аут.
  Этот тест использует Worker Node как проверочный стенд и НЕ доказывает
  безопасность браузерной границы.
- `node scripts/test-code-runtime.mjs` — отдельный интеграционный тест
  браузера через localhost; `node scripts/test-code-isolation.mjs` —
  отдельный автономный тест CSP. Требуется Edge либо путь в переменной
  `NOTEAPP_TEST_BROWSER`.

В среде агента браузерные тесты заблокированы ограничениями localhost /
запуска Edge. Проверки реальных движков и сборки выполняются отдельно;
проверка Tauri/WebView2 целиком пока не подтверждена. Поэтому автоматическая
проверка изоляции перед активацией запуска обязательна и не должна удаляться
ради включения кнопки.
